Design spec · 2026-07-02

Pre-enable evaluation nudge + honest evaluation loop

Requirement #3 of the approval-tags session. Scope grounded in WORKFLOW_BENCHMARK Part D, P1-4 "Tests that test THIS doc". Paired with 2026-07-02-eval-nudge-loop-design.md (canonical).

Problem

The evaluation panel produces confidence without information: every run replays one canned 6-step API-error trace (SIM_TRACE) regardless of what the document says, "Passed" is undefined, there is no summary rollup, and nothing connects evaluation to Enable. An admin can take an untested AOP live without ever being told that testing exists.

Goal

  • Traces walk the real document, so a run is evidence about THIS AOP.
  • A plain-language n-of-m rollup summarizes the runs (Fin has per-sim verdicts but no rollup - this is differentiation).
  • Recent conversations becomes a true backtest: the doc runs against a real past thread, compared with what the team actually did (Pylon's pattern, email-native).
  • Enable is evaluation-aware: skippable nudge when never evaluated, caution variant on failures, quiet status row when everything passed.

Decisions locked (2026-07-02)

  • Scope = honest loop + backtest. Post-live Runs surface stays out (Agent View brief).
  • Nudge shows only when the AOP has never been evaluated, plus a caution variant on failures. Once evaluated, Enable never re-nags.
  • Enable flow is status-aware: the eval aggregate lifts up to the canvas.
  • Branch-aware traces: the trace enters the taken condition arm and walks its action lines; untaken arms are absent.
  • Stale handling = note only: edits after a run mark the rollup "evaluated an earlier version"; no re-nudge; re-running clears it.

1 · deriveTrace(doc, email)

New pure module components/simulate/deriveTrace.ts. Outputs the existing TraceStep shape, so the shipped RunTrace renderer is reused untouched (one renderer per pattern).

Branch-aware: names the arm taken (scripted per fixture email, default first arm), then walks only that arm's body lines.
  • Outcomes stay scripted per fixture email (passed / failed / attention) - no real model calls. failAt becomes semantic: fail at the first connector step if one exists, else at the last action step - always a real step of THIS doc.
  • Draft reply card shows only when the doc actually contains a draft-reply action.
  • Empty doc: existing empty states gate entry; the deriver still returns a defensive trigger-only trace if reached.
  • SIM_TRACE is deleted once all three flows consume the deriver.

2 · Eval aggregate lifted + summary strip

  • New useEvalState hook owned by EditorCanvas: { total, passed, failed, attention, stale } + recordRun.
  • SimulatePanel gains doc (the deriver needs it) and onRunRecorded. Topic results + thumbs verdicts stay local - nothing above consumes them.
  • Staleness: content signature captured at run time (step order, text, chip actionId + config, branches; volatile ids ignored). Any meaningful edit sets stale; re-running clears it.
3 passed   1 failed   4 evaluations · Evaluated an earlier version of this AOP
Summary strip: one line above the eval entry cards once anything has run. Plain text + status dots, no card chrome.

3 · Pre-enable nudge + Enable wiring

Has failures (failed > 0) Caution variant: "1 of 4 evaluations failed." Review results   Enable anyway

Chrome: same overlay/card family as EnableModal, calm fade, reduced-motion aware. The settings gear (manage mode) never nudges. The nudge is skippable, never blocking.

4 · Backtest - Recent conversations

  • Recent-email fixtures gain teamDid: tags applied, reply sent, assignment, escalation - what the team actually did on that thread.
  • After a run, the result card adds a compare block: "AOP would have" (key actions distilled from the derived trace, rendered with the Chip atom in plain mode) vs "Your team did", with row-per-aspect match / differs markers.
  • One plain-language verdict line: "Matches what your team did" or "Differs - your team also escalated to Billing."
  • On differs: "Adjust the AOP for this case" pre-fills the Copilot composer and switches to the Copilot tab. Pre-fill only - the user sends.
  • AI scenarios + Custom email keep their current result presentation, now derived.

Out of scope (explicit)

  • Post-live Runs surface, failure inbox, run-to-step links (PRD Section 9 / Agent View).
  • Author-set success criteria (Fin's four assertion types) - the ceiling, not this pass.
  • The full P0 readiness engine (red blocks / amber warns strip).
  • Create-from-history (P0-1).
  • Real model calls - the honesty fix is scripted outcomes landing on real steps of the real doc.

Verification + build order

Playwright-core screenshot loop on localhost (the established gate): author a doc with a tag chip, an approval gate and a condition; run all three flows; verify the trace mirrors the doc (approval pause step, branch entry); fail an email and check rollup + caution nudge; fresh doc for the untested nudge; all-pass for the EnableModal row; edit for the stale note. Copy pass, tsc + lint clean, PNGs deleted.

  • 1. deriveTrace + swap into useSimRun (all three flows honest)
  • 2. Eval aggregate lift + summary strip
  • 3. Nudge modal + EnableModal status row + wiring
  • 4. Backtest fixtures + compare block + Copilot pre-fill

Each stage lands as its own reviewable commit on a feature branch; PR after adversarial self-review; merge only on Varun's go-ahead.
